# Бот-каталог O&A cosmetics (@Olga_Shutova_bot)

Telegram-бот на aiogram 3: каталог косметики с кнопками, админка `/admin`, покупатели не могут писать в чат.
Пользователь — не программист, общаемся по-русски, объясняем по шагам.

## Где что работает
- **Сервер:** Bothost.ru, тариф «Базовый» (99 ₽/мес, оплачен 08.10.2026 на 30 дней), регион Нидерланды.
  Бот собирается из GitHub-репозитория, обновление — кнопка 🔄 «обновить из Git» на карточке бота.
  Внешнего API для редеплоя у Bothost нет. Вебхук автообновления на GitHub добавлен, но отвечает 401
  (токен в ссылке Bothost меняется при каждой загрузке страницы) — не полагаемся на него.
- **Пользователь вошёл в Bothost во встроенном браузере (Claude_Browser) и разрешил нажимать кнопки самому:**
  dashboard.php → карточка бота → кнопка с title «Обновить из Git» (`updateBot(...)`), логи — «Показать логи».
  Останавливать/удалять бота без прямой просьбы нельзя.
- **GitHub:** https://github.com/daniilstrekalev0201/oa-cosmetics-bot (public, ветка main).
- **Локально бота НЕ запускать**, пока он работает на сервере (Conflict getUpdates). Локальный `.env` содержит старый, отозванный токен.

## Каталог живёт в Telegram, а не в products.json
- `cloud.py`: копия каталога — закреплённый документ `products.json` в чате первого админа из `ADMIN_IDS`.
  При запуске бот берёт каталог оттуда (`pull`), после каждой правки в админке обновляет его (`push`).
- Поэтому правка `products.json` в репозитории на сервер НЕ попадает. Данные меняются через `/admin`,
  а разовые изменения данных из кода — через `apply_updates()` в `bot.py` (с меткой в `catalog["done"]`).
  Список таких обновлений — `UPDATES` в bot.py (сделаны: ozon_skus, insta_posts — кнопки «👀 Пост в Instagram»).
  Кнопка «🌐 Смотреть на сайте» добавляется кодом в `product_kb` (ссылка `SITE_URL/#p-<id>`), в каталоге её нет.
- `ADMIN_IDS` на Bothost: `974443828,487846393` (владелец Даниил первым — копия каталога у него; Ольга @Shutova_Olga).
  Порядок важен. Без переменной используется `DEFAULT_ADMIN_IDS` из `catalog.py`.

## Файлы
- `bot.py` — покупательская часть, запрет писать в чат (lockdown), меню команд, `apply_updates`.
- `admin.py` — админ-панель (товары, поля, фото, разделы, кнопки, тексты).
- `catalog.py` — загрузка/сохранение каталога, `product_text`, список админов.
- `cloud.py` — хранение каталога в Telegram.
- `website.py` — сайт-витрина (aiohttp в том же процессе, порт PORT=3000): `/`, `/photo/{id}`, `/go/{товар|shop}/{i}`
  (редирект + подсчёт кликов), `/logo.jpg`, `/health`. Не называть модуль `site.py` — конфликт со stdlib.
  Адрес: https://oacosmetics.bothost.tech (09.10.2026; старый bot-1791469457-...bothost.tech отключён).
  Смена имени домена в Bothost: после «Сохранить» прокси может отдавать 404 — помогает повторный вызов
  `fetch('api/bot-settings.php',{method:'POST',body:JSON.stringify({action:'update_domain',id:BOT_ID,enabled:true,domain:...,internal_port:3000})})`
  на странице bot-manage.php (ответ route_ok:true). Переменная DOMAIN в контейнере при этом остаётся старой.
- `stats.py` — статистика (/admin → 📊): ID и даты покупателей без админов, в `DATA_DIR`/stats.json
  (на Bothost /app/data — постоянный диск). Нажатия URL-кнопок Telegram не сообщает — считать через будущий сайт.
- `для GitHub/` — чистая копия для загрузки на GitHub через сайт (без `.env`). Обновлять её при изменении кода.

## Как выкатывать изменения кода (всё делаем сами)
1. Правим код, гоняем офлайн-тесты (заглушки сообщений, копия каталога во временной папке).
2. `D:\бот косметика` — git-репозиторий, связан с origin/main, `gh` авторизован (аккаунт daniilstrekalev0201).
   Git установлен в `D:\Git`, gh — в `D:\GitHub CLI` (по просьбе пользователя). Если их нет в PATH сессии:
   `$env:Path = "D:\Git\cmd;D:\GitHub CLI;" + $env:Path`.
   Коммитим и пушим: `git add <файлы>; git commit -m "..."; git push`. `.env` в .gitignore — проверять `git status` перед коммитом.
   Автор коммитов — noreply-адрес GitHub (репозиторий публичный, личную почту не светим).
3. Встроенный браузер → bothost.ru/dashboard.php → «Обновить из Git». Кнопка вызывает нативный confirm(),
   который встроенный браузер отклоняет, поэтому вызываем через JS:
   `window.confirm=()=>true; await updateBot('bot_1791469457_9104_daniilstrekalev')` (вернуть confirm обратно).
   Проверяем «История деплоев» (запись ✅ с текущей датой) и «Показать логи». Если сессия Bothost слетела —
   просим пользователя войти во встроенном браузере (пароль не вводим сами).
4. Папка `для GitHub/` устарела (в .gitignore) — больше не нужна.
